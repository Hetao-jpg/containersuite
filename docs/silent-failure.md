    // [REG] 结构化回归标记（原 RegMark 类，2026-10-13 并入本类）。
    // 一行一个实例，供 _regress\regress.ps1 机器解析；人也能直接读。
    //   [REG]    id=<ascii> status=PASS|FAIL|NA detail=<任意文本>
    //   [REG.BP] name=<ascii> detail=<任意文本>       ← 断点：关键状态转换处留痕

    // 设计原则（与 MEMORY 一致）：
    //   · id / name 一律 ASCII（避开编码坑），中文只进 detail。
    //   · 只加日志，不改任何逻辑、不改任何判据、不改任何写权限。

## C-2（2026-10-12）：去重集合 **不做** 整体 Clear（`ContainerSuiteLog.cs` / `DiyUpgradeMod.Utils.cs`）

> 由批次3 从源码搬迁（源码保留关键契约 + 指针）。共同结论：对**去重集合**用
> `CacheLimits.Trim`（语义 = 超限即整体 Clear）是错的 —— 清空后旧 key 立刻可重打，
> 玩家看到"同一个错又出现了"，反而误判为功能反复出错（= 制造假信号）。

```
        // ★ C-2（2026-10-12）：删除此处的 CacheLimits.Trim。
        //   原注释的理由是"整体清空后重复打印少量旧 key 无害"—— 对去重集合不成立：
        //   一旦整体清空，**已经打过的诊断点会在同一会话里再打一遍**，看起来像
        //   "这个状态又出现了一次"（去重信息丢失 = 制造假信号）。
        //   key 由调用方**显式指定**（诊断点本身，不是消息文本），种类有限；
        //   有界性交给 CacheRegistry 的场景/读档清空（ClearDiagOnce），不依赖这条兜底。
        //   ★ 新增调用方时请确保 key 是固定诊断点 —— 若把物品 id / 坐标拼进 key，
        //     键空间就变成单调增长，需要另行加淘汰（参照 DIY 的 EvictOldestLogKeys）。
```

```
    /// <summary>
    /// C-2（2026-10-12）：去重集合的**有界淘汰** —— 只丢最旧的一批，不清空整体。
    /// <para>
    /// ★ 为什么不再用 <c>CacheLimits.Trim</c>：Trim 的语义是「超限即整体 Clear」。
    ///   对**去重集合**用整体 Clear 是错的 —— 清空后旧 key 立刻可以重新打印，
    ///   玩家看到"同一个错又出现了"，反而误判为功能反复出错。
    /// </para>
    /// <para>
    /// ★ 为什么仍要淘汰：key 是消息文本，而部分调用点把物品 id / 槽号 / WxH 拼进了
    ///   消息（见 GridWindow 的拖拽告警），键空间随玩家操作**单调增长** ⇒
    ///   「会话内消息种类天然有限」这个假设不成立，不能完全不设上界。
    ///   按"最后打印时间"淘汰最旧的一批：被淘汰的正好是长期没再出现的消息，
    ///   近期活跃消息的去重信息不丢。
    /// </para>
    /// <para>
    /// ★ 只在这里调用（热路径），超限时才排序，正常情况是 O(1) 判空返回。
    /// </para>
    /// </summary>
```
