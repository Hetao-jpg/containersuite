二、关键事实更正（影响后续所有判断，先读）
================================================================================

1. 【B-3 前提错误】DirectoryMaster.Item(identifier) 不保证返回玩家操作的那一个实例。
   PSKit API 存档（build/api/api.md）：「static GameItem Item(string identifier,
   bool isOwned = true)」；pskit-store-client/references/tag-scanner.cs:46 注明
   isOwned=false 为「模板物品」。场上存在两个同型容器时（两个 storage_bay 很常见），
   按标识符查表可能解析到另一个实例 → 协程会升级错容器、吞错材料。
   原 B-3 说「材料无法用 id 查表」只对一半：identifier 是类型级字符串，
   每实例 id 是 uniqueId（MetaKey = id#uniqueId，见 Meta.cs:98-108）。

2. 【B-3 校验无效】Il2CppObjectBase.Pointer 就是包装器里存的那个指针，
   「持有快照对象 + 比对 Pointer」是恒真式，永远不可能触发。
   RestoreArbiter.cs:228 的同款检查同理，真正有信号的是 item.state == null。
   照抄它等于加一个看着活着、永远不响的检查 —— 正是要避免的静默失效。

3. 【B-3 AV 前提不成立】Marshal.ReadIntPtr 读已释放但未解映射的 IL2CPP 堆
   不会抛 AccessViolation；真实危害是地址复用后操作到别的物品上。

4. 【C-1 过时描述】MustWarmLeaves（Restore.cs:606-616）只覆盖 [JitWarmup]
   声明的叶子；7 个入口 Prefix 是 Patch() 里手动 WarmupRegistry.Register 的，
   删调用即自动注销，MustWarmLeaves 无需改动。回归也不锁预热数量
   （jit.warm.text 只查「预热完成」存在性）。

5. 【C-1 过时描述】当前 README.md.txt 里没有「#13」也没有「入口层 7 个 Prefix」
   （这些说法在 _archive 的旧 README 里）。真正要更新的是
   readme.用户须知.md:105 的示例日志「Wage 避让：14/14 成功」→ 改 7/7。
   _regress/checks.json 的 wage.avoid.text 是 N/N 两数相等判定，无需改。

6. 【环境】_shared\check-forbidden.ps1（R1~R6 门禁，含 R6「Cache/Seen 字段
   必须登记」）在本工作区不存在，D:/games 下也搜不到。计划里的「门禁」步骤
   目前跑不了，需先恢复该脚本，否则 R6 无编译期看守（新增缓存漏登记不会被拦）。

7. 【环境】D:/games/mod调试/ContainerSuite.* 是旧版源码树（缺 S8u-4 旁路存档、
   S9 页归属自愈等，与 open code work 树已大幅分叉）。所有改动只针对
   D:/games/open code work/ContainerSuite，不要改错树。

为什么要收窄（原计划用 CacheRegistry.ClearAll() 的问题）:
  ClearAll 会连 _offsetCache 一起清（Core.cs:192 登记）。_offsetCache 的键是

  触发的调用点就在恢复深栈上（Meta.LoadMeta 路径），正是 2026-10-10 读档闪退
  修复（Patches.cs:596-605 注释）想避免的「深栈上首次执行」类操作。
  另外：显式再调一次 ClearRestoreMemo() 是冗余 —— _restoreMemo 已登记
  （Core.cs:187），ClearAll/ClearForLoadGame 都覆盖它。

原方案被否决的原因（执行前必读，防止"顺手改回去"）:
  ① 按 id 查表会升级错容器：DirectoryMaster.Item(identifier) 返回的是"按标识符
     可拥有的实例/模板"，不保证是玩家拖落的那一个；两个同型容器在场上时，
     协程可能对着另一个容器吞材料。指针才是"拖落了什么"的唯一事实。
  ② 「持有 GameItem 快照 + 比对 Pointer」是恒真式：Il2CppObjectBase.Pointer 就是

  ③ AV 前提不成立：读已释放但未解映射的 IL2CPP 堆不抛 AccessViolation；
     真实危害是地址复用后操作到别的物品。
  ④ 跨帧持有包装器违反本文件头 R4 教训（"存指针而非 GameItem 对象"）。

B-3' 的思路（最小修订，10 行量级）:
  快照时在活对象上读一次 uniqueId（每实例 id，浅栈、安全），执行时每步
  「new GameItem(ptr) → 比对 uniqueId」—— 地址被复用成别的物品时 uid 必然
  不同，直接跳过/中止。不持对象、不改签名语义、不动文件头 doctrine。

                : $"批量升级中 {_groupDragProgressCurrent}/{_groupDragProgressTotal}";

            float w = Mathf.Min(Screen.width - 80f, 420f);
            var rect = new Rect((Screen.width - w) * 0.5f, 90f, w, 30f);
            var shadow = new Rect(rect.x + 2f, rect.y + 2f, rect.width, rect.height);

            _groupDragProgressStyle.normal.textColor = new Color(0f, 0f, 0f, alpha * 0.8f);
            GUI.Label(shadow, txt, _groupDragProgressStyle);
            _groupDragProgressStyle.normal.textColor = new Color(1f, 1f, 1f, alpha);
            GUI.Label(rect, txt, _groupDragProgressStyle);
        }
        catch (Exception ex) { CatchLogOnce.Warn("GroupDrag:draw-progress", ex); }
    }
