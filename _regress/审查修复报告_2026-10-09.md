# ContainerSuite 可读性与稳健性审查 · 修复报告

- 日期：2026-10-09
- 范围：`ContainerSuite.Shared` / `ContainerSuite.Infrastructure` / `ContainerSuite.SaveBag` / `ContainerSuite.DIYUpgrade`（`_analysis`、`_archive`、`_S*备份`、`_B1测试前备份` 等参考/备份目录不在范围）
- 产出：Release 构建 **0 警告 / 0 错误**；P4（版本）、DOC（默认值）、FBD（禁用模式）三个静态守卫全部通过。

---

## 一、执行决策（经用户确认）

1. **保留全部临时诊断脚手架** —— `[TRACE]` 打点、`CrashTraceHeartbeat` 心跳协程、启动期 `WarmupJit` / `WarmupSaveLoadChain` 预热一律不删，只修其无害缺陷（心跳不再整场空转）。
2. **反编译残留命名全部重命名** —— 但**仅限方法内的局部变量与参数**；**不改字段/属性/方法/类型名**（`DiyUpgradeMod` 由 20 个 partial 文件共享状态，跨文件改名会破坏编译）。除个别经 Grep 全工程确认无外部引用的类型/字段外，均未触碰成员名。

## 三、验证结论

1. **构建**：`dotnet build ContainerSuite.sln -c Release` → 0 警告 / 0 错误，P4/DOC/FBD 通过。
2. **编译期修复**：修掉 1 个错误 —— `SkipXiaowoBayRestore` 中 `IDictionary.Remove` 返回 `void`（非泛型接口），改为先 `Contains` 再移除。
3. **重命名一致性**：被删成员/旧类型名的剩余引用为 0；`BoxRefArgs/BeadRefArgs/GetTagIntSafe/OwnsWageBox` 在编译范围内零命中；DIYUpgrade 内已无 `int/var num*/flag*/text*/val*` 形式的残留局部声明。
4. **行为变更逐项核对**：`IsMouseOver` 角点、`WritePrimaryTags` 判据、`BeginDrag` 计数守卫、`Cursor.Tick` try 包裹均语义正确。
5. **运行时关键项（编译器不可验证）已人工核对**：`SkipXiaowo` 7 个补丁目标签名与 `_analysis\libmods\XIAOWOTradePerks.cs` 逐一比对，全部匹配（详见下表）。

## 四、有意保留（未改，附原因）

- 全部临时诊断脚手架（[TRACE] / 心跳 / JIT 预热）——按用户决定保留。
- `CacheLimits.Trim` 的 `Count > limit` —— 与被替换掉的原始裸写法语义一致，改 `>=` 会造成清空更频繁的回归。
- `CfgMigration` 的「moved==0 即 return 不写标记」——属设计上的重试防线，无法证实是缺陷。
- `WageContainerRegistry._diyVoidBeadGrids`（`IntPtr` 裸指针集合）——`DiyUpgradeMod.Core.cs` 每场景已 `ClearVoidBeadGrids`，场景内指针复用属理论风险、改动面大，未纳入本次。
- `OffsetResolver.FindOffsetField` 的「包含匹配」兜底 —— 已有注释说明，保留。
